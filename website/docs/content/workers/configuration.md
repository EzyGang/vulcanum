# Worker configuration

The worker reads `~/.vulcanum/config.json`. On first start, it creates the file with default values if the file does not exist.

## Fields

| Field | Default | Allowed value or purpose |
| --- | --- | --- |
| `harness` | `"host"` | Isolation mode: `host`, `docker`, or `kata` |
| `image` | `"ghcr.io/ezygang/vulcanum/agent:latest"` | Container image for Docker and Kata jobs |
| `log_format` | `null` | Set to `"json"` for JSON logs |
| `debug` | `false` | Enables debug-level logs |
| `poll_interval_secs` | `30` | Delay after a poll returns no job |
| `auto_update_enabled` | `true` | Enables verified updates of the installed `vulcanum` CLI and `vulcanum-server` worker daemon release pair |
| `update_check_interval_secs` | `86400` | Update interval in seconds; from 60 through 31536000 |

Example:

```json
{
  "harness": "docker",
  "image": "ghcr.io/ezygang/vulcanum/agent:latest",
  "log_format": "json",
  "debug": false,
  "poll_interval_secs": 30,
  "auto_update_enabled": true,
  "update_check_interval_secs": 86400
}
```

Use `vulcanum worker updates enable` or `vulcanum worker updates disable` to change only the update setting. A running daemon applies the changed setting on its next startup.

## Worker identity

`~/.vulcanum/worker.json` is not an operator configuration file. Setup writes:

- worker ID;
- control-plane instance URL;
- access token;
- refresh token;
- token expiration;
- maximum concurrent jobs.

Do not edit this file. Use `vulcanum worker setup --force` to replace a registration.

## Automatic updates

Automatic updates replace the installed `vulcanum` CLI and `vulcanum-server` worker daemon as one verified release pair. They do not update the control plane or frontend. Newly created worker configurations enable automatic updates by default.

Use the local worker CLI to opt out or back in:

```bash
vulcanum worker updates disable
vulcanum worker updates enable
```

Each command changes only `auto_update_enabled`; all other worker configuration fields are preserved. A running daemon applies the changed setting on its next startup.

When enabled, the daemon checks at startup and after each interval. It waits until no new or recovered job is active or queued. It selects the latest non-prerelease GitHub release for the current Linux or macOS architecture.

The updater:

1. Downloads the archive and checksum used by `install.sh`.
2. Verifies SHA-256.
3. Requires both worker-side binaries.
4. Runs the staged daemon in preflight mode.
5. Saves the current pair and version marker in `<install-dir>/.vulcanum-rollback/`.
6. Records an activation transaction.
7. Replaces the full pair.
8. Restarts the worker service.
9. Commits only after configuration, connectivity, journal, and recovery initialization succeed.

A failed or interrupted activation restores the previous pair. Never restore only one binary.

### Update prerequisites

The service account needs:

- HTTPS access to `api.github.com` and the Vulcanum GitHub releases;
- write access to the directory that contains both binaries;
- non-interactive permission to restart the worker service;
- both binaries in the same install directory.

Linux restarts `vulcanum-worker` with systemd. macOS uses the `com.vulcanum.worker` launchd service.

### Manual recovery

If the filesystem prevents automatic rollback:

1. Stop the worker service.
2. Copy `vulcanum`, `vulcanum-server`, and `.vulcanum-version` together from `.vulcanum-rollback/` to the install directory.
3. Remove `.vulcanum-update-state`.
4. Preserve executable mode on both binaries.
5. Start the service.

You can also run `install.sh` with a pinned `VULCANUM_VERSION`. Restart the worker service after installation.
